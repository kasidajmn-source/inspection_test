# Construction Checklist — เว็บแบบฟอร์มตรวจสอบงานก่อสร้าง

เว็บไซต์ไฟล์เดียว (`index.html`) ไม่ต้อง build ไม่ต้องลง dependency ใดๆ เปิดใช้ได้ทั้งบนเครื่องและบน GitHub Pages

## ฟีเจอร์

**งานเอกสาร**

- ข้อมูลโครงการ: ชื่อโครงการ / เลขที่สัญญา / วันที่ตรวจสอบ / ผู้รับจ้าง / ผู้ว่าจ้าง / สถานที่ / งวดงาน / ผู้ตรวจสอบ / สภาพอากาศ / ช่วงเวลา
- เลขที่เอกสาร + แก้ไขครั้งที่ + ใส่โลโก้หน่วยงาน (คลิกกล่องสีเหลืองมุมบนซ้าย)
- รายการตรวจสอบแบ่งเป็นหมวด แต่ละรายการมี **ผ่าน / ไม่ผ่าน / N.A. + หมายเหตุ + เกณฑ์อ้างอิง**
- เทมเพลตสำเร็จรูป: งานโยธา/ก่อสร้างอาคาร (7 หมวด 40 รายการ) และ งานถนน/ระบบระบายน้ำ (7 หมวด 35 รายการ) หรือเริ่มจากฟอร์มเปล่า
- **คลังเทมเพลตของตัวเอง** — บันทึกชุดรายการที่แก้เองไว้ใช้ซ้ำกับงานหน้า (เมนู ⋯ → บันทึกเป็นเทมเพลตของฉัน)
- แก้ไขข้อความทุกช่องได้โดยตรง เพิ่ม/ลบ/ทำสำเนา/เลื่อนหมวด และปุ่ม "ให้ผ่านทั้งหมวด" สำหรับหมวดที่ผ่านหมด

**หน้างาน**

- **แนบรูปถ่าย** ได้ไม่จำกัดจำนวนต่อรายการ พร้อมคำบรรยายใต้ภาพ — ย่อรูปอัตโนมัติเหลือด้านยาว 1200px คุณภาพ 72% (รูปจากมือถือ 4 MB เหลือราว 150–250 KB) และแทรกลงใน PDF ให้เอง
- **ลายเซ็นอิเล็กทรอนิกส์** — แตะเส้นลงนามแล้วเซ็นด้วยนิ้วบนมือถือหรือลากเมาส์บนคอม ลายเซ็นติดไปใน PDF
- **บันทึกพิกัด GPS + วันเวลา** ปุ่มเดียว ใช้เป็นหลักฐานว่าตรวจที่หน้างานจริง (ต้องอนุญาตสิทธิ์ตำแหน่งในเบราว์เซอร์)
- **โหมดกรอกเร็ว** ⚡ — ซ่อนช่องที่ไม่จำเป็น ปุ่ม ผ่าน/ไม่ผ่าน/N.A. ใหญ่ขึ้นสำหรับกดด้วยนิ้ว และเลื่อนไปข้อถัดไปให้อัตโนมัติหลังกด

**ควบคุมงาน**

- **ใบสั่งแก้ไข (Defect list)** — รวบเฉพาะรายการที่ไม่ผ่าน พร้อมรายละเอียด รูปประกอบ กำหนดวันแก้ไข และช่องว่างสำหรับบันทึกผลตรวจซ้ำ พิมพ์เป็น PDF แยกฉบับส่งผู้รับจ้างได้
- **กำหนดวันแก้ไข + สถานะแก้ไขแล้ว** ในรายการที่ไม่ผ่าน (ช่องจะโผล่ให้เองเมื่อกด "ไม่ผ่าน")
- **สร้างรอบตรวจซ้ำ** — สร้างงานตรวจรอบใหม่ที่มีเฉพาะรายการที่ไม่ผ่าน พร้อมแนบผลรอบก่อนไว้ในหมายเหตุ และติดป้าย "ตรวจซ้ำ รอบที่ N" บนเอกสาร
- **เก็บหลายงานตรวจในเครื่องเดียว** — สลับงานจากช่องเลือกบนแถบเครื่องมือ ทำสำเนา หรือลบได้ แยกข้อมูลกันคนละชุด
- สรุปผลอัตโนมัติ: รายการทั้งหมด / ผ่าน / ไม่ผ่าน / N.A. / ยังไม่ตรวจ

**เอกสาร PDF**

- กดปุ่ม "PDF" → เลือกปลายทางเป็น Save as PDF
  - เว็บแบ่งหน้า A4 เองก่อนส่งให้เบราว์เซอร์พิมพ์ ทุกหน้าจึงมีระยะขอบเท่ากัน หัวตารางไม่ขาดกลางหน้า และหมวดที่ต่อหน้าจะขึ้นหัวหมวดใหม่พร้อมกำกับ "(ต่อ)"
  - ไม่มี URL / วันที่ / ชื่อไฟล์ ของเบราว์เซอร์ติดขอบกระดาษ มีแต่หัวกระดาษและเลขหน้า "หน้า X / Y" ของเอกสารเอง
  - ถ้าใช้ Safari หรือ Firefox แล้วยังเห็นวันที่/URL ติดขอบ ให้ติ๊กออกที่ช่อง Headers and footers ในหน้าต่างพิมพ์
  - รายการที่ไม่ผ่านถูกไฮไลต์ให้เห็นชัด และปิดท้ายด้วยช่องลงนาม 3 ฝ่าย
- บันทึกอัตโนมัติลงเครื่อง + ส่งออก/นำเข้า JSON (เฉพาะงานนี้ หรือทุกงานพร้อมกัน)

## วิธีขึ้น GitHub Pages

วิธีที่ 1 — เว็บเดี่ยวที่ `https://<username>.github.io`

1. สร้าง repository ชื่อ `<username>.github.io` (ตั้งเป็น Public)
2. อัปโหลด `index.html` ไว้ที่ root ของ repo
3. รอ 1-2 นาที แล้วเปิด `https://<username>.github.io`

วิธีที่ 2 — เป็นโปรเจกต์ย่อยของ repo ที่มีอยู่

1. อัปโหลด `index.html` ขึ้น repo (branch `main`)
2. ไปที่ **Settings → Pages** → Source: `Deploy from a branch` → Branch: `main` / โฟลเดอร์ `/ (root)` → Save
3. เปิด `https://<username>.github.io/<repo-name>/`

ผ่าน command line:

```bash
git init
git add index.html
git commit -m "add construction checklist"
git branch -M main
git remote add origin https://github.com/<username>/<repo>.git
git push -u origin main
```

## ข้อควรรู้

- ข้อมูลและรูปทั้งหมดเก็บไว้ใน **เบราว์เซอร์ของเครื่องที่กรอกเท่านั้น** ไม่ได้ส่งขึ้นเซิร์ฟเวอร์ (เปิดคนละเครื่องจะไม่เห็นข้อมูลกัน)
- เบราว์เซอร์ให้พื้นที่ราว 5 MB ต่อเว็บหนึ่งเว็บ — ด้วยการย่อรูปอัตโนมัติจะเก็บได้ราว 20–30 รูป เช็คได้ที่เมนู ⋯ → พื้นที่ที่ใช้ ถ้าใกล้เต็มให้ส่งออก JSON เก็บไว้แล้วลบงานเก่าออก
- อยากย้ายงานไปเครื่องอื่นหรือส่งให้เพื่อนร่วมงาน ใช้ ⋯ → ส่งออก JSON แล้วให้ปลายทาง ⋯ → นำเข้า JSON (รูปและลายเซ็นติดไปด้วย)
- ฟอนต์ใช้ Sarabun จาก Google Fonts ถ้าเปิดออฟไลน์จะ fallback เป็นฟอนต์ระบบ แต่ใช้งานได้ปกติ
- แก้เทมเพลตตั้งต้นได้ในไฟล์ `index.html` ที่ตัวแปร `TEMPLATES` (ในแท็ก `<script>`)
- ข้อมูลจากเวอร์ชันก่อนหน้าจะถูกย้ายเข้าระบบหลายโครงการให้อัตโนมัติเมื่อเปิดครั้งแรก
